## 长任务中的记忆问题

Agent Harness 里面，在 long-horizon agent 场景下存在 memory 的问题。之前的主流做法有两种：

- 压缩上下文，对之前的流程进行摘要。
- 使用 RAG 技术进行存储，在需要的时候查询。

## Fold：复用原始信息的历史压缩

近期在网上看到了一种压缩历史信息的新方法，原作者称之为 Fold。作者希望尽量不使用传统的“让模型 summarize”的方式，而是使用每轮对话的原始信息进行“压缩”。

### 大致流程

1. 当上次 Fold 之后积累了一定数量的工具调用或 Token，系统向模型提供一张 Fold Card，列出可以考虑折叠的历史区间、涉及的文件路径、工具调用数量以及用户的原始指令。
2. 模型根据语义判断哪些工作已经完成，并通过工具调用指定需要折叠的回合范围。
3. Host 将这部分原始对话归档，再用一条更精简的结果记录替换当前上下文中的原始消息。

### 结果记录

更精简的结果记录包括：

- **机械统计信息**：这段工作调用了多少次工具、涉及哪些文件路径等，由程序直接统计。
- **用户原始指令**：保留用户当时的原话，避免丢失具体需求和约束。
- **模型已有的收尾消息**：直接复用模型在工作结束时已经生成的结论，不再额外调用模型总结。

Fold 不会再额外调用一次模型来重新总结历史，而是直接复用已有信息构造结果记录。工具调用数量、涉及的文件路径等统计信息由程序机械提取，逐字保留用户原始的输入，工作的最终结论则直接取自模型在任务结束时已经生成的收尾消息。这样既减少了重复总结的成本，也降低了二次总结时遗漏关键信息的风险。

### 触发时机

作者提出，不要等到上下文快满时再做“压缩”，因为这样会有更高的成本。可以使用工具调用数量作为参考，比如每调用 100 次工具，就开始考虑是否需要进行 Fold。
